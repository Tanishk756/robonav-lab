# Launch measurement plan

The release does not install a remote analytics tracker. Usage counting is explicitly opt-in and stays in localStorage on the current device. It records only demo starts, mission completions, share actions and completed local challenges. Opting out clears those counters. Export is user-initiated. These counts do not measure total public visitors or prove reach.

For the first launch, collect voluntary feedback and use the hosting/platform statistics already available to the maintainer. Keep a simple log of channel, post date, actual impressions, link clicks if reported, relevant technical feedback and reproducible issues. Leave unavailable values empty rather than estimating them.

Useful questions: can visitors identify the tool's purpose, start a demo, explain a failure and share a setup? Distinguish views from completed experiments. Avoid inferring causation from one post or promising a reach target.

If aggregate site analytics are later required, choose an explicit provider and data policy first. Do not silently switch local counters into remote collection. Do not collect map contents, URL fragments, personal identifiers or cross-site profiles by default.

Suggested cadence: publish the visual demonstration first, respond to technical questions, then use the route-cost and doorway clips in separate posts when there is a relevant explanation to add. No exact posting time or guaranteed engagement is asserted.
